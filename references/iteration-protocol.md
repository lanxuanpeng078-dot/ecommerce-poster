# 课程作业轻量迭代方案

## 四种“训练”

| 方法 | 实际改变什么 | 课程用途 |
|---|---|---|
| 真正模型训练/微调 | 模型参数，需要支持训练的模型、授权数据、训练流程与预算 | 当前不开展；改 Skill 或聊天不会自动改变模型权重 |
| 提示词与示例驱动 | 每次输入的任务说明、正反例 | 优先使用，记录完整输入与示例选择 |
| 规则与参考图迭代 | SKILL、品类策略、构图约束、参考图及其说明 | 优先使用，每轮改 1–3 项，保留修改前版本 |
| 评测集与版本管理 | 固定测试输入、评分标准、变更记录 | 用于检验是否改善，本身不训练模型 |

## 第一轮材料

收集老师作业要求、评分标准、截止时间；选择一个有授权商品图的商品，提供名称、规格、真实卖点、价格及活动规则（无活动须明确填无活动）、目标人群、尺寸。准备 3–5 张有来源的参考图，每张写明喜欢/不喜欢的具体原因。不要把未提供的案例当作已有数据。

## 固定小型实验

1. 建立 8 个输入案例：4 个用于开发、4 个封存用于最终验收。开发覆盖食品、美妆、3C、家居；验收覆盖服饰、跨类商品、缺促销信息、冲突信息。每例绑定相同商品图、参考图、文案和任务目标；暂缺素材则标未就绪，不伪造测试结果。
2. 冻结本轮修改前的版本作为基线（本轮为 v4.3）。先完成文字流程冒烟测试，再对 2 个有完整素材的代表案例做成图对照，控制课程成本。
3. 每轮只改变一个实验变量，例如信息层级规则、参考例或商品占比；其余模型、工具设置、输入文件、选择方向、尺寸保持一致。记录可获得的模型版本和随机种子；工具不提供则写未暴露。
4. 原版和候选版各生成 2 次（预算允许可增加），保留所有输出，不挑最好的一张作唯一结果。生成过程有随机性，不能保证像素级复现。
5. 先过事实与保真硬门槛，再按原有 100 分量表评分；固定 200 px 宽缩略图，全文核对数字，并由同学盲评 3 秒识别结果。记录评分人、图像证据与分歧；自评只能作辅助。
6. 晋级条件预先确定：无新增硬错误；完整成图平均分比基线提高至少 5 分，且单例不下降超过 5 分。这个阈值是课程实验约定；样本很小，不声称统计显著或真实转化提升。达不到则保留基线并记录失败原因。
7. 最终版本在封存集上一次验收。若看到失败后再修改，该集已成为开发集，另补新的封存案例。最多三轮后总结瓶颈。

## 版本与实验记录

保留 `v4-original`、`v4.1-baseline`、`v4.2-candidate` 的独立快照或 Git 提交；不要仅依赖聊天记忆。每次记录日期、版本、唯一改动、假设、案例编号、输入文件哈希、工具/模型、完整提示词、参数、方向选择、输出路径、硬错误、各项分数、耗时与成本（可获得时）、保留或回退结论。

课程报告展示：问题 → 基线失败证据 → 单变量改动 → 同输入前后图 → 评分与局限 → 最终版本。完成评测后才把证实有效的规则写回 Skill；单次偏好保留为案例，不升级为通用规则。

## 迭代执行入口与记录

识别训练 Skill、优化规则、增加案例、修正分类错误后，记录问题和最小复现输入 → 读取相关文件 → 备份基线 → 做针对性修改 → 检查引用和跨文件冲突 → 回放相关用例 → 记录结果、局限和版本。用户明确要求的一组规则修订可集中实施，但不要把多项改动的效果归因于单一变量。规则编辑与成图实验分别记录。

“优化这张海报”仍走设计评价；“优化 Skill 的规则”走本协议。目的不清时先澄清，不自动生成图或改写技能。

### v4.4 回归用例（待实际行为测试）

| 输入 | 预期行为 |
|---|---|
| 信息完整但属于其他类别 | 提供三个分类路径选项，等待选择，不跳到设计方向 |
| 普通计步手环，无医疗用途资料 | 采用消费电子分类或说明不确定，不因健康数据认定医疗属性 |
| 六项清单后仍缺四项关键内容 | 本轮集中问最多三项，保持信息不足，下一轮可继续收集 |
| 无价格证据、无参考图 | 保留价格带与图号字段，标待核实/参考图缺失，不编造 |
| A/B/C 仅换背景颜色 | 重构创意与叙事，不将其作为合格三方案 |
| 全部不满意，重新构思 | 保留已确认事实与策略，返回阶段 4 |
| 取消设计 | 输出简洁快照，不继续出图 |
| 修正分类规则 / 只把当前标题缩小 | 前者走 Skill 迭代，后者走海报修改 |

每例记录输入、实际输出、通过/失败/未测、证据路径、失败原因和版本。静态检查通过不等于行为测试通过；无实际回放不得填写通过。
## v4.5 三图流程回归用例（待实际行为测试）
- 完整资料且未选方向：实际生成并展示 A/B/C 三张独立预览，不提前制作最终稿。
- 只根据文字选过 A：保留 A 偏好，补齐三图后再选择。
- 已从实际三图选择 B：直接制作 B 最终稿，不重复要求选择。
- 仅生成 A，B/C 失败：说明未完成，按主流程限次重试，不以文字补足，不声称三图齐备。
- 全部不满意：重新生成三张差异化预览，保留已确认事实。

## v4.7 视觉质量规则修订（待成图验证）

试用反馈：商品与背景环境融合偶有不真实；输出清晰度与商品细节不足；版式选择偏单一。

修改范围：主流程新增场景/光线/透视融合、保护商品原图像素、源图细节边界和导出清晰度检查；首图参考扩充构图机制并规定 A/B/C 的版式结构差异；评价量表增加融合、细节、清晰度与版式重复检查。保留原有三图选择门、品类分类和素材使用规则。

状态：规则已更新，尚未用固定案例执行前后成图对照；改善程度待验证。验证时选至少两个素材完整案例，固定商品图、方向、尺寸与生成工具设置，记录原版/新版输出；检查 100% 局部、实际投放尺寸和结构性版式差异。只有满足原协议的硬门槛与晋级条件后，才记录为通过。
